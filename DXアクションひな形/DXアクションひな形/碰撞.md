# 遊戲引擎物理管線：PNG 像素轉 Box2D 碰撞體積實作指南

本文件概述在 C++ 與 DirectX 遊戲引擎架構下，將手繪 PNG 圖像轉換為 Box2D 物理碰撞體的完整工作流。此管線分為「離線資料處理（Offline Pipeline）」與「引擎執行期（Runtime）」兩個階段。

---

## 階段一：離線工具開發 (Offline Pipeline)
此階段的目標是開發一個獨立的 C++ 工具，將美術輸出的 PNG 圖檔預先處理成輕量化的物理頂點資料，避免在遊戲執行時消耗 CPU 資源。

### 1. 讀取像素 Alpha 通道
利用輕量級影像讀取庫解析圖檔，提取透明度資訊。
* **推薦函式庫**：`stb_image.h` 
* **實作邏輯**：
  * 載入 PNG 圖檔並讀取其 RGBA 像素陣列。
  * 遍歷陣列，設立 Alpha 閾值（例如：Alpha > 128 視為實體，Alpha < 128 視為透明）。
  * 建立一個與原圖尺寸相同的二維布林陣列，標記實體與空白區域。

### 2. 邊緣輪廓追蹤 (Contour Tracing)
從二維陣列中提取出圖片實體區域的邊緣座標，轉換為向量頂點。
* **推薦演算法**：Marching Squares (行進方塊法) 或 Moore-Neighbor Tracing (摩爾鄰域追蹤)。
* **實作邏輯**：
  * 掃描布林陣列尋找第一個實體像素邊界。
  * 沿著實體與透明交界處進行追蹤，記錄下每一個經過的像素座標 `(x, y)`。
  * 確保輸出的頂點陣列具備連續性與方向性（順時針或逆時針）。

### 3. 頂點簡化 (Vertex Simplification)
原始追蹤產生的像素級頂點過於密集，會導致物理引擎效能低落及碰撞判定不平滑，必須進行降維處理。
* **推薦演算法**：Ramer-Douglas-Peucker (RDP) 演算法。
* **實作邏輯**：
  * 設定一個容差值 $\varepsilon$ (Epsilon)。
  * 透過 RDP 演算法剔除對整體形狀影響小於 $\varepsilon$ 的冗餘頂點。
  * 經過測試調整 $\varepsilon$ 值，在「保留手繪不規則輪廓感」與「物理碰撞表面平滑度」之間取得平衡。

### 4. 序列化與資料匯出
將簡化後的頂點座標儲存為遊戲引擎可快速讀取的格式。
* **匯出格式**：自定義二進位檔（`.bin`）或 JSON（開發期較易除錯）。
* **資料結構**：包含圖檔名稱關聯、頂點總數、以及序列化的 `(x, y)` 座標陣列。

## 階段二：引擎主程式實作 (Engine Runtime)
在主程式中分離渲染與物理邏輯，將載入的頂點資料交給 Box2D 處理物理模擬，並將 DirectX 渲染對齊 Box2D 的運算結果。

### 1. DirectX 視覺渲染載入
* 在遊戲初始化時，透過 DirectX (如 `DirectX::CreateWICTextureFromFile`) 將原始手繪 PNG 載入 GPU 作為材質 (Texture / Sprite)。
* 該材質僅作為視覺呈現，不包含任何物理資訊。

### 2. Box2D 物理碰撞重建
讀取階段一匯出的頂點資料檔，並在 Box2D 世界 (`b2World`) 中建立對應的剛體。

* **地形 / 空心平台 (使用 `b2ChainShape`)**：
  * 適用於單純的地面或不規則的跳躍平台邊緣。
  * 建立靜態剛體 (`b2BodyDef.type = b2_staticBody`)。
  * 實作程式碼範例：
    ```cpp
    b2ChainShape chainShape;
    chainShape.CreateLoop(verticesArray, vertexCount); // 或 CreateChain
    b2FixtureDef fixtureDef;
    fixtureDef.shape = &chainShape;
    body->CreateFixture(&fixtureDef);
    ```

* **實心物件 / 動態圖案 (需凸分解)**：
  * 若手寫圖案是會掉落、具備質量的動態物件，由於 `b2PolygonShape` 僅支援凸多邊形，需套用 Bayazit 演算法將凹多邊形切割。
  * 將切割出的多個小凸多邊形，逐一掛載到同一個 `b2Body` 的 Fixture 上。

### 3. 渲染與物理迴圈同步
在遊戲主迴圈 (Game Loop) 中，嚴格遵守「物理計算先於渲染」的原則。
1. **Physics Step**：呼叫 `world->Step(...)` 進行物理模擬。
2. **Transform Sync**：從 Box2D 的 `b2Body` 獲取最新的位置 `GetPosition()` 與旋轉角度 `GetAngle()`。
3. **Render**：將取回的物理座標轉換為 DirectX 的螢幕/世界座標，並呼叫 Draw API 繪製對應的 PNG 材質。
